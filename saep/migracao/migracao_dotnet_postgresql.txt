MIGRACAO PARA .NET + POSTGRESQL
Guia tecnico de implementacao
Sistema: Quiz Caca ao Tesouro
Objetivo: permitir que outro dev ou IA reconstrua o sistema atual em ASP.NET Core + PostgreSQL

1. OBJETIVO

Este documento transforma a documentacao funcional em um plano tecnico de implementacao para:
- ASP.NET Core Web API
- Entity Framework Core
- PostgreSQL
- JWT para autenticacao
- jobs em background

O objetivo nao e apenas migrar dados.
O objetivo e reconstruir o comportamento atual do sistema com arquitetura de backend propria.

2. RESULTADO ESPERADO

Ao final da migracao, o novo sistema deve manter:
- cadastro com restricao de dominio
- confirmacao de e-mail
- aprovacao de usuario
- lobby com resumo do jogador
- desafio unico por janela
- tentativa unica por usuario
- retomada da participacao em andamento
- pontuacao baseada em tempo, erros e dificuldade
- ranking individual acumulado
- ranking por sala por media dos usuarios ativos
- titulos e medalhas
- historico de desafios
- painel admin para desafios, salas e usuarios

3. STACK RECOMENDADA

Backend:
- .NET 8 ou superior
- ASP.NET Core Web API
- Entity Framework Core
- Npgsql Entity Framework Provider
- FluentValidation

- mapear enums como string ou int

Recomendacao:

19. VALIDADOR DE REGRAS IMPORTANTES

Criar validacoes explicitas para:
- e-mail institucional
- nome minimo de usuario
- quantidade de questoes > 0
- fim_em > inicio_em
- sala nao pode ser excluida se houver usuarios vinculados
- usuario nao pode ter segunda participacao no mesmo desafio
- usuario concluido nao pode reiniciar desafio

20. FLUXO TECNICO DE START CHALLENGE

Pseudo fluxo:

1. Buscar desafio atual valido
2. Se nao existir, retornar state = sem_desafio
3. Buscar participacao por desafio + usuario
4. Se nao existir:
   - carregar banco de questoes e charadas
   - sortear conteudo
   - criar participacao em andamento
   - retornar state = novo
5. Se existir e status = concluido:
   - retornar state = concluido
6. Se existir e prazo vencido:
   - marcar expirado
   - retornar state = expirado
7. Senao:
   - retornar state = retomar

21. FLUXO TECNICO DE FINISH CHALLENGE

Pseudo fluxo:

1. Carregar participacao
2. Validar se pertence ao usuario
3. Validar se ainda nao concluiu
4. Calcular score
5. Atualizar participacao:
   - status = concluido
   - concluido_em
   - pontuacao
   - tempo
   - erros
6. Atualizar cache/ranking
7. Calcular titulos desbloqueados
8. Retornar resumo final

22. COMO REPRESENTAR TITULOS NO BACKEND

Opcao simples:
- nao persistir todos os titulos por usuario
- calcular em tempo de agregacao

Opcao com persistencia:
- tabela user_titles

Recomendacao para primeira versao:
- calcular em agregacao
- persistir apenas no cache de ranking

Motivo:
- e fiel ao comportamento atual
- reduz escrita

30. RECOMENDACAO FINAL

Se a prioridade for reproduzir o sistema atual com menor risco:
- implementar primeiro a API
- testar todos os fluxos com Postman ou Swagger
- so depois reconstruir ou adaptar o frontend

Se o frontend atual for mantido por um tempo:
- criar a API em paralelo
- adaptar tela por tela
- trocar gradualmente o Firebase pelo backend novo

Para uma migracao segura e incremental:
- manter o comportamento
- centralizar regras no backend
- usar snapshots de participacao
- tratar ranking como agregacao com cache
